# SEO

## Metadata Strategy

Metadata is defined at two levels:

1. **Root layout** (`app/layout.tsx`): default values applied to all pages
2. **Individual pages** (`app/*/page.tsx`): page-specific overrides

Next.js merges them automatically via `metadata.title.template`.

---

## Title Tags

Template: `"%s | ARKANA"`

Page titles follow the pattern: `Page Name | ARKANA`

Example: `IT-аутсорсинг в Ташкенте | ARKANA — Технологический партнёр` (homepage, no template applied)

## Open Graph

Every page has Open Graph metadata. The root layout defines defaults; inner pages override `og:title`, `og:description`, and `og:url`.

```ts
openGraph: {
  type: "website",
  locale: "ru_RU",
  alternateLocale: ["en_US", "uz_UZ"],
  url: SITE_URL,
  siteName: "ARKANA",
  title: "...",
  description: "...",
  images: [{ url: `${SITE_URL}/og-image.png`, width: 1200, height: 630 }],
}
```

OG image: `/og-image.png` (1200×630 px) — stored in `public/`.

## Canonical URLs

Each page sets its canonical URL:

```ts
alternates: { canonical: "/services/it-outsourcing" }
```

The root layout sets the site-wide canonical to `SITE_URL` (`https://arkana.uz`).

---

## hreflang

Since language switching is client-side (no URL changes per locale), all four hreflang entries point to the same domain. This is valid per Google guidelines for client-side language switching.

```ts
alternates: {
  languages: {
    "ru":        "https://arkana.uz",
    "en":        "https://arkana.uz",
    "uz":        "https://arkana.uz",
    "x-default": "https://arkana.uz",
  },
}
```

## Structured Data (Schema.org / JSON-LD)

Structured data is injected as `<script type="application/ld+json">` tags. Multiple schemas can appear on one page.

### Root layout (all pages)

**Organization**:
```json
{
  "@type": "Organization",
  "name": "ARKANA",
  "url": "https://arkana.uz",
  "logo": { "@type": "ImageObject", "url": "/logo-3d.png", "width": 512, "height": 512 },
  "telephone": "+998 78 888 44 88",
  "contactPoint": [
    { "@type": "ContactPoint", "contactType": "sales", "availableLanguage": ["ru","uz","en"] },
    { "@type": "ContactPoint", "contactType": "technical support" }
  ]
}
```

**LocalBusiness / ProfessionalService**:
```json
{
  "@type": ["LocalBusiness", "ProfessionalService"],
  "name": "ARKANA",
  "priceRange": "$",
  "areaServed": [
    { "@type": "City", "name": "Tashkent" },
    { "@type": "Country", "name": "Uzbekistan" }
  ],
  "hasOfferCatalog": { ... 4 services ... }
}
```

### Service pages

Each service sub-page (`/services/it-outsourcing`, `/services/itsm`, etc.) injects a `Service` schema:

```json
{
  "@type": "Service",
  "name": "IT Outsourcing",
  "alternateName": "IT Аутсорсинг",
  "provider": { "@id": "https://arkana.uz" },
  "areaServed": [ "City:Tashkent", "Country:Uzbekistan" ]
}
```

### Blog posts

Each blog post injects `Article` and `BreadcrumbList`:

```json
{
  "@type": "Article",
  "headline": "...",
  "datePublished": "...",
  "author": { "@type": "Organization", "name": "ARKANA" }
}
```

### Builder functions

`lib/seo.ts` exports three builder functions:

```ts
buildArticleSchema({ slug, title, excerpt, date })
buildBreadcrumbSchema([ { name, url }, ... ])
buildFaqSchema([ { question, answer }, ... ])
```

## Sitemap

Auto-generated at `/sitemap.xml` by `app/sitemap.ts`. Contains 18 URLs.

Update frequency and priority by content type:
- `/` : weekly, priority 1.0
- `/pricing`, `/goarkan` : weekly, priority 0.9
- `/services`, `/cases`, `/blog`, `/contact` : monthly or daily, 0.8
- Service sub-pages : monthly, 0.7
- Blog articles : monthly, 0.6

**Sitemap URL** in `robots.txt`: `https://arkana.uz/sitemap.xml`

## Search Engine Verification

Verification codes are injected via `metadata.verification`:

```ts
verification: {
  google: process.env.NEXT_PUBLIC_GOOGLE_SITE_VERIFY,   // <meta name="google-site-verification">
  yandex: process.env.NEXT_PUBLIC_YANDEX_VERIFICATION,  // <meta name="yandex-verification">
}
```

If env vars are not set, the meta tags are not rendered (no error).

## Analytics

**Google Analytics 4 (GA4)**:
- Set `NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX`
- Loaded via `<Script strategy="afterInteractive">` — deferred, does not block render

**Yandex.Metrika**:
- Set `NEXT_PUBLIC_YANDEX_METRIKA_ID=XXXXXXXX`
- Loaded via inline script in `<head>` with async flag
- Includes webvisor, clickmap, bounce tracking
- `<noscript>` fallback image for no-JS environments

Both analytics scripts only load when their respective env vars are set. They are completely absent in development unless explicitly configured.

## Image Optimisation

All images use `next/image` which:
- Serves WebP/AVIF format based on browser support
- Adds lazy loading by default (`loading="lazy"`)
- Reserves layout space via `width`/`height` props to prevent CLS
- Applies `priority` to above-the-fold images (logo in Navigation, hero images)

The `og-image.png` is a static file in `public/` — not processed by `next/image` since OG images must be served as raw URLs.
